Ограниченный сертификат минцифры

Личный root CA + name-constrained proxy корня «Russian Trusted Root CA». Доверие минцифре только для доменов из вашего списка. Всё генерируется локально в браузере — ключи никуда не отправляются. Исходники страницы — в каталоге web/src репозитория проекта.

По одному в строке; поддомены включаются автоматически (gosuslugi.ru покрывает и www.gosuslugi.ru). Комментарии после # игнорируются.
По умолчанию сертификаты выпускаются бессрочными (до 9999-12-31).
Файл root.pem из прошлой генерации (приватный ключ + сертификат). Если не указан — будет создан новый root. Если NC вашего root не покрывает новый список доменов — сертификат root будет перевыпущен на том же ключе.

Результат

Сохраните root.pem! Файл содержит приватный ключ вашего CA. Потеряете — новая генерация потребует новый root и переустановку сертификатов на всех устройствах. Храните файл в безопасном месте; при необходимости защитите паролем (age / 7z / зашифрованный архив).

Проверки

Установка (после скачивания файлов)

Скачайте файлы и выполните команды. Замените пути на свои.

Linux (openssl / ca-certificates) 
sudo cp root.crt /usr/local/share/ca-certificates/restricted-ru-root.crt
sudo cp proxy.crt /usr/local/share/ca-certificates/restricted-ru-proxy.crt
sudo update-ca-certificates

Firefox использует собственное хранилище: настройте корпоративную политику policies.json с "certificates": {"Install": ["/path/root.crt", "/path/proxy.crt"]} или импортируйте через certutil -d db:.

Windows (cmd от администратора) 
certutil -addstore -f Root root.crt
certutil -addstore -f CA proxy.crt
macOS 
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain root.crt
sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain proxy.crt
Android

Отдельного хранилища промежуточных сертификатов в Android нет: оба файла устанавливаются по очереди как «Сертификат ЦС» и каждый становится доверенным якорем — это нормально и работает. root.pem не устанавливать (приватный ключ).

  1. Настройки → Безопасность (и конфиденциальность) → Ещё → Шифрование и учётные данные → Установить сертификат → Сертификат ЦС → выберите root.crt, затем повторите для proxy.crt. Названия пунктов отличаются у вендоров (Samsung: «Установить сертификат из хранилища устройства»). Android потребует задать PIN; предупреждение «Сеть может отслеживаться» — норма для пользовательских ЦС.
  2. Проверка: Настройки → Безопасность → Доверенные сертификаты → вкладка «Пользователь» — должны появиться обе записи; у записи про минцифры «Кем выдан» — ваш личный root.
  3. Полностью перезапустите Chrome: наберите в адресной строке chrome://restart.
  4. Удаление: тот же экран «Доверенные сертификаты → Пользователь» → удалить обе записи → снова chrome://restart и убедиться, что список опустел.

Firefox на Android использует собственное хранилище сертификатов — эта схема к нему не применима.

Удаление

Linux: удалите /usr/local/share/ca-certificates/restricted-ru-*.crt и запустите sudo update-ca-certificates --fresh. Windows: certutil -delstore Root "restricted-russian-ca Personal Root" и удалите proxy из промежуточного хранилища. macOS: sudo security delete-certificate -c "restricted-russian-ca".

Как проверить сгенерированные сертификаты (openssl)

Перед установкой убедитесь, что сертификаты именно такие, как задумано: ваше имя, нужный срок, ограничение доменов и совпадение ключа proxy с рутом минцифры.

# кто, кем выпущен и на какой срок
openssl x509 -in root.crt -noout -subject -issuer -dates
openssl x509 -in proxy.crt -noout -subject -issuer -dates

# отпечаток root — сверьте со значением SHA256 из «Результата» выше
openssl x509 -in root.crt -noout -fingerprint -sha256

# nameConstraints: critical, Permitted: DNS из вашего списка, Excluded: IP
openssl x509 -in proxy.crt -noout -text | grep -A10 "Name Constraints"

# публичный ключ proxy обязан совпадать с публичным ключом рута минцифры
# (две команды должны выдать одинаковый хэш)
openssl x509 -in proxy.crt -pubkey -noout | openssl sha256
openssl x509 -in pinned/mincifry-root.crt -pubkey -noout | openssl sha256

# цепочка: сертификат суб-CA минцифры проверяется вашим root + proxy
openssl verify -CAfile root.crt -untrusted proxy.crt pinned/mincifry-sub-ca.crt

После установки можно проверить живой сайт (example — доверенный домен):

# proxy.crt нужен цепочке как промежуточный — подаём оба файла одним бандлом
cat root.crt proxy.crt > bundle.pem
openssl s_client -connect gosuslugi.ru:443 -servername gosuslugi.ru \
  -CAfile bundle.pem </dev/null 2>/dev/null | grep "Verify return"
# → Verify return code: 0 (ok). Для домена вне списка будет ошибка — это ожидаемо.

Как это работает

Оригинальный рут минцифры не устанавливается. Вместо него ставятся: ваш личный root и proxy-сертификат, в котором скопированы имя и публичный ключ рута минцифры, но подписан он вашим root и содержит критическое расширение nameConstraints: доверие только DNS-именам из вашего списка, IP-сертификаты исключены. Сайты вне списка будут отклоняться с ошибкой сертификата — это ожидаемое поведение.
